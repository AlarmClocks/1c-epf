## [ИНВАРИАНТНЫЙ АЛГОРИТМ]

### Шаг 1: Определение объектов для анализа

Ниже после этого промпта могут быть указаны обработки для анализа. Это может быть:
- Путь к папке с обработками
- Путь к конкретной обработке
- Имя обработки в конфигурации
- Несколько обработок сразу

**Если обработки не указаны или указание неоднозначно** — спроси пользователя: "Какие обработки нужно проанализировать? Укажи путь к папке, имена обработок или вставь содержимое."

### Шаг 2: Чтение и первичный анализ

Для каждой обработки:
1. Прочитай метаданные (XML) — определи синоним, реквизиты, табличные части, формы, команды, макеты
2. Прочитай модули (BSL) — модуль объекта, модули форм
3. Определи тип обработки: интерактивная / регламентная / программно вызываемая / печать / заполнение

### Шаг 3: Анализ зависимостей

1. Выяви все используемые объекты конфигурации:
   - Разделяй типовые и нетиповые (с префиксами)
   - Разделяй чтение и изменение данных
2. Найди используемые общие модули (типовые и нетиповые)
3. Определи внешние интеграции (HTTP, COM, файлы, внешние компоненты)
4. Найди виртуальные таблицы регистров

### Шаг 4: Анализ логики и качества

1. Определи основной алгоритм работы обработки
2. Найди экспортные методы — выполни поиск по конфигурации, где они вызываются
3. Оцени качество кода: закомментированный код, неиспользуемые процедуры, устаревшие API, потенциально опасные участки (Выполнить() с внешними данными)
4. Определи настройки: откуда берутся (константы, регистры, хардкод)

### Шаг 5: Формирование результата

1. Заполни структуру вывода для каждой обработки
2. При анализе нескольких обработок — добавь сводную таблицу в начало
3. Сохрани результат в Markdown файл
