## [ИНВАРИАНТНЫЙ АЛГОРИТМ]

### Шаг 1: Определение объектов для анализа

Ниже после этого промпта могут быть указаны отчеты для анализа. Это может быть:
- Путь к папке с отчетами
- Путь к конкретному отчету
- Имя отчета в конфигурации
- Несколько отчетов сразу

**Если отчеты не указаны или указание неоднозначно** — спроси пользователя: "Какие отчеты нужно проанализировать? Укажи путь к папке, имена отчетов или вставь содержимое."

### Шаг 2: Чтение и первичный анализ

Для каждого отчета:
1. Прочитай метаданные (XML) — определи синоним, тип (СКД/обычный), формы, варианты, макеты
2. Прочитай схему СКД (если есть) — наборы данных, поля, параметры, ресурсы
3. Прочитай модули (BSL) — модуль объекта/менеджера, модули форм
4. Определи способ использования: из меню / программно / в фоне / встроен в форму

### Шаг 3: Анализ источников данных

1. Извлеки все источники из запросов СКД и программного кода:
   - Разделяй типовые и нетиповые объекты (с префиксами)
   - Определи виртуальные таблицы (Остатки, Обороты, ОстаткиИОбороты)
2. Найди используемые общие модули (типовые и нетиповые)
3. Определи внешние источники данных (HTTP, файлы, COM)

### Шаг 4: Анализ структуры и качества

1. Определи основные показатели (ресурсы) и разрезы (группировки)
2. Найди параметры, отборы и варианты отчета (выдели нетиповые варианты с префиксами)
3. Определи программные доработки СКД: модификация запросов, вычисляемые поля, условное оформление в коде
4. Оцени качество: неоптимальные запросы, неиспользуемые поля, устаревшие механизмы

### Шаг 5: Формирование результата

1. Заполни структуру вывода для каждого отчета
2. При анализе нескольких отчетов — добавь сводную таблицу в начало
3. Сохрани результат в Markdown файл
